# PROJECT.md — captions-clone

## What this is
Web app that auto-captions talking-head video and adds AI B-roll (generated or stock), modelled on captions.ai. Locked spec: `docs/spec.md`; architecture + evidence: `docs/blueprint.md` (full reverse-engineering report lives in `~/Desktop/Reverse Engineer/captions-ai-reverse-engineering.md`).

## Where things live (why)
- Repo lives at `~/Developer/captions-clone` on the Mac (moved from the SSD on 2026-10-18). Heavy *large* files only go to the SSD: `DATA_DIR=/Volumes/PortableSSD/Bong/captions-clone-data` holds uploads, renders and Hugging Face model weights (`HF_HOME=$DATA_DIR/hf`).
- **Never put code dependencies on the SSD**: it is ExFAT with a 1 MiB allocation block, so every small file costs 1 MiB (`node_modules` was 28 GB there; a whisperX venv + uv cache filled the drive). `node_modules`, the whisperX `.venv` (`ai/transcription/.venv`, git-ignored) and the uv cache stay on the Mac. The Mac has little free space (~5 GB on 2026-10-18): the torch-based venv is ~3 GB — check `df -h /` before `npm run ai:whisperx`. Heavy data (uploads, renders, models, Postgres/MinIO volumes) under `DATA_DIR=/Volumes/PortableSSD/Bong/captions-clone-data` — keeps the Mac's disk free.
- Ollama model blobs (large files) live on the SSD too: `npm run ai:ollama` serves with `OLLAMA_MODELS=$DATA_DIR/ollama`. Use the Ollama **CLI** (`brew install ollama`), never the menu-bar app — it autostarts its own server with models on the Mac disk.
- Hybrid architecture: `frontend/` (Vite+React+Tailwind v4), `backend/` (Express 5, `createApp(deps)` composition root), `shared/` (`contract.ts` = the only wire contract), `ai/`, `database/schema/schema.sql` (idempotent, applied on api boot), `infrastructure/docker/`.
- One root `package.json`, no workspaces. Aliases `@`, `@ai`, `@shared` exist for frontend only; backend imports stay relative.

## Run / verify
Processes (terminal tabs, or `.claude/launch.json` entries `api-lite`, `dev`, `whisperx`, `ollama`):
1. `npm run ai:whisperx` — whisperX sidecar on :8010 (first run: `uv` installs torch/whisperx into `ai/transcription/.venv` on the Mac (~3 GB), then downloads the `small` Whisper model + a wav2vec2 aligner into `DATA_DIR/hf` on the SSD).
2. `npm run dev:lite` — API with in-memory repos, files under `DATA_DIR` (debug here first); `npm run dev:server` needs `DATABASE_URL` (`make db` starts Postgres + MinIO; Docker Desktop must be running).
3. `npm run dev` — Vite on :5173 proxying `/api` → :3001.
4. `npm run ai:ollama` — Ollama on :11434 for "Plan edit" (shots, emphasis, emoji, translation). Not installed yet (2026-10-18): `brew install ollama` → `npm run ai:ollama` in its own tab → `ollama pull qwen2.5:3b` (~1.9 GB, served by that instance so it lands on the SSD). `OLLAMA_MODEL=qwen2.5:7b` (4.7 GB, fits 16 GB RAM) translates ja/ko/zh/hi/tl noticeably better, ~2× slower. Captions (`/run`) never need Ollama.
5. **Claude as the editor** (plan 3, spec row 10): API running (any of the above; `api-lite-fake` is enough) + optionally `npm run dev` for the live web preview → open a Claude Code session **in the repo folder** → approve the project MCP server `sabi` (`.mcp.json`: `npx tsx backend/mcp/index.ts`, `SABI_API_URL=http://127.0.0.1:3001`) → 9 tools (`list_projects inspect_project render_frame apply_actions run_job wait_job create_project upload_asset export_outputs`); skill `.claude/skills/sabi-editor` teaches the loop (plus `motion-graphics.md` for agent-written MGs). B-roll/brand/MG loop: `run_job plan` → `run_job broll` → `inspect_project {section: "broll"}` → `apply_actions` (`setOverlay`, `replaceOverlay` after `upload_asset`, `setBrand`, `addMotionGraphic`…) → `render_frame` → `run_job render`. `npm run mcp` runs the server by hand (stdio; logs on stderr only). A session started in another folder never sees `.mcp.json`; `claude mcp list` in the repo shows it as "Pending approval" until approved.
- `FAKE_AI=1 npm run dev:lite` (launch entry `api-lite-fake`) swaps whisperX, Ollama, **Pexels and fal.ai** for fakes (sample transcript, deterministic plan, "Spanish: …" translations, a 1×1 PNG as every stock/generated image; fake videos fail the probe and are skipped) so the whole UI can be driven with only ffmpeg + Chrome.
- B-roll providers (both optional; a project whose media source needs a missing one fails its B-roll job with `stock_unavailable` / `generator_unavailable` and keeps everything): `PEXELS_KEY` (free, https://www.pexels.com/api/, 200 req/h) for "Stock only" and as the per-beat fallback; `FAL_KEY` for "Generate (fal.ai)": `fal-ai/flux/schnell` ≈ $0.003/image (ledgered as 1 ¢), one video beat per project with `fal-ai/kling-video/v1.6/standard/image-to-video` ≈ $0.25. `creditsUsedCents` on the project sums it (no billing).
- Uploads accept images too (`image/png`, `image/jpeg`, `image/webp`; ≤ 50 MiB, ≤ 8192 px) for logos, overlay replacements and MG image props. Uploads from a script: `POST /api/assets/uploads/start` → `PUT /api/assets/uploads/:id` → `POST …/done` → `POST /api/projects/:id/source`.
- `npm run verify` = typecheck (web + server) + vitest (241 tests). Tests are colocated; the API is tested with supertest against `createApp(makeTestDeps())` (fake media/transcriber/renderer).
- `npm run render:sample` — real Remotion renders (needs Google Chrome; ~90 s): captions, cuts, a still, a top-band overlay, a brand-graded clip with an MG, a throwing MG (⚠ placeholder) and an endless-loop MG (render fails in ~40 s); the layer tests sample pixels with ffmpeg.
- Renders use the installed **Google Chrome** (`REMOTION_BROWSER_EXECUTABLE` to override): Remotion's own chrome-headless-shell never starts from the ExFAT SSD. First bundle (webpack → `.remotion-bundle/`) takes ~1 min.
- Local ffmpeg has no libass/freetype: all text is drawn by Remotion; ffmpeg only probes and extracts 16 kHz WAV, with `-protocol_whitelist file` + a format whitelist (uploads are untrusted).

## Decisions
- **Claude is the editing agent, on subscription only (spec §11 row 10, 2026-10-20):** a Claude Code sidebar session drives projects through Sabi's MCP server (`backend/mcp`, `.mcp.json`, skill `.claude/skills/sabi-editor`). The backend never calls Claude or any Anthropic API; web buttons stay on Ollama. Plan 3 (B-roll) is paused on `worktree-broll-and-overlays` until the MCP plan lands.
- **MCP server shape (plan 3):** `backend/mcp` is an HTTP client of the API, never an in-process import (works with dev:lite and dev:server; the web preview updates over SSE). Writes go through `POST /api/projects/:id/actions` — typed actions, all-or-nothing, guarded by `baseVersion` = the `updatedAt` Claude last saw (`409 stale` → re-inspect; ms resolution). `render_frame` uses `GET …/frame` = Remotion `renderStill` with `captionVideoProps`, so frames are **output** time and match the export; `inspect_project` prints source times plus `→ out` times when cuts are on. Tool results stay small (summary lists capped at 30, phrases paged, search instead of dumps). File tools only touch paths under `$HOME`; `export_outputs` never overwrites or follows an existing file (`<title> (n)`).
- **Motion graphics = Remotion components, not HyperFrames (spec row 11):** the agent sends plain JS+JSX; the server transpiles it with the TypeScript compiler (`typescript` is a runtime dependency) and vets the AST (`backend/modules/mg/compile.ts`: no imports/exports, a denylist of globals, network, timers, code-from-string, HTML-from-string, spread attributes and string-built property names) and stores `code` + `compiled`. The server **never executes** it: `compiled` runs only in Chrome (Remotion render, `GET /frame`, browser Player) via `new Function` with an explicit scope and an error boundary that draws `⚠ mg-<n>`. The denylist is a guard rail, not a sandbox — a sandboxed iframe/CSP is the real boundary (open decision, see State).
- **Brand kit (row 12):** `project.brand` (palette, `fontFamily`, `logoAssetId`, `grade`) recolours captions (text, accent = active word + keywords, primary = nouns/pictorial), feeds every MG as `item.brand`, and grades footage + B-roll (CSS saturate/contrast + a soft-light tint of `primary`). Fonts must be installed on the rendering Mac (Google-font loading = plan 4). Layer order in `CaptionVideo`: footage → B-roll overlays → tint → MGs → captions.
- **One write path for layers:** overlays, MGs and the brand kit change only through `POST …/actions` (web panel and MCP alike); only fetching media is a job (`POST …/broll`). Overlays are drawn only over `B-Roll` / `Talking Head & B-Roll` shots (others are "stale" until the next B-roll run); remote media is copied into storage (`importRemote`: https only, ≤ 50 MiB, typed, probed with per-kind demuxers) so renders never fetch third-party hosts.
- **The API answers only this machine (no auth, solo):** CORS allows localhost origins only, writes with a non-local `Origin` get `403 cross_origin`, and `/api` requests whose `Host` is not localhost/127.0.0.1/[::1]/`apiBaseUrl`'s host get `403 bad_host` (DNS rebinding) — so a web page can't edit projects or spend fal credits. Phone testing on the LAN: `npm run dev -- --host` + `ALLOWED_ORIGINS=http://<mac-ip>:5173` on the API. Docker sets `API_BASE_URL=http://api:3001` (the render browser inside the network) and nginx forwards the browser's own Host.
- Commits and PRs carry **no Claude/AI co-author trailers or "Generated with Claude Code" lines** (owner's rule: they appear as GitHub contributors). `.githooks/commit-msg` strips them; `npm install` (`prepare`) sets `core.hooksPath`.
- LLM = Ollama locally (never Anthropic API — billing rule). Generation = fal.ai by default, per-project `mediaSource: "stock"` switches to Pexels only.
- Project model is JSON in Postgres (jsonb), not protobuf; render engine = Remotion/FFmpeg server-side (not in-browser WASM) for MVP.
- Shot taxonomy copied from captions.ai: `Hook | B-Roll | Talking Head | Talking Head & B-Roll`.
- Edit plan (plan 2): cuts are heuristic only (`shared/editing/cuts.ts`: ASR gap > 600 ms padded 150 ms, filler lexicon, no cuts when there is no non-filler word); the LLM only labels (shots, ≤ 2 emphasis words/phrase, emoji) and translates, always via `askJson` (zod-validated JSON, bounded arrays, one retry with the rejection fed back). Everything is stored in source time; `captionVideoProps()` maps it onto the cut timeline for both the Remotion render and the browser preview, so preview = export. Translations are independent subtitle tracks; burn-in replaces the original captions. A failed LLM step restores the previous status and keeps old outputs; a fresh `/run` or new source clears plan, translations and burn-in.
