# PROJECT.md — captions-clone

## What this is
Web app that auto-captions talking-head video and adds AI B-roll (generated or stock), modelled on captions.ai. Locked spec: `docs/spec.md`; architecture + evidence: `docs/blueprint.md` (full reverse-engineering report lives in `~/Developer/Reverse Engineer/captions-ai-reverse-engineering.md`).

## Where things live (why)
- **Storage (2026-10-20): everything heavy lives on the PortableSSD, in two forms.** (1) Large files go straight onto the SSD (ExFAT): `DATA_DIR=/Volumes/PortableSSD/Bong/captions-clone-data` holds uploads, renders, Hugging Face weights (`HF_HOME=$DATA_DIR/hf`), Ollama blobs and Postgres/MinIO volumes. (2) Small-file dev storage — the repo and its worktrees, the whisperX `.venv`, the uv cache (`.cache/uv`, set by `npm run ai:whisperx`) and the npm cache (`~/.npmrc` `cache=~/SabiDev/npm-cache`, shared by all projects) — lives in the **SabiDev APFS image** `/Volumes/PortableSSD/Bong/sabi-dev.sparsebundle` (growable, 100 GB cap, mounted at `~/SabiDev`). The repo moved there on 2026-10-20: `~/Developer/captions-clone` is a symlink to `~/SabiDev/captions-clone`, so every path keeps working.
- **`node_modules` stays on the Mac** (`~/Developer/.sabi-deps/<checkout>/node_modules`, `<checkout>` = `main` or the worktree folder name), and each checkout's `node_modules` is a symlink to it. Inside the image, module reads over USB made `npm run verify` take 7½ min instead of 24 s and `dev:lite` boot in 154 s instead of 1 s. **Never run plain `npm install` in the repo**: npm replaces the symlink with a real folder on the SSD. Use `npm run deps` (`infrastructure/dev/deps.sh`; extra args go to `npm install`, e.g. `npm run deps -- zod@4`): it installs in the Mac folder, copies `package.json`/`package-lock.json` back and keeps the link. A new worktree: `npm run deps` from inside it (first run fills `~/Developer/.sabi-deps/<name>` from the npm cache).
- **Never put small files directly on the ExFAT SSD:** 1 MiB allocation blocks make every small file cost 1 MiB (`node_modules` was 28 GB there; a whisperX venv + uv cache filled the drive; ~160–200 GB estimated for today's dev files vs ~11 GB in the image). Inside the APFS image they cost their real size.
- **SabiDev must be mounted to develop:** the login item `~/Library/LaunchAgents/com.febriel.sabidev-mount.plist` attaches it at login and whenever a disk mounts (≈10 s after plugging in the SSD). Eject with **`~/Applications/Eject Sabi SSD.app`** (unmounts SabiDev, detaches the image, ejects PortableSSD; SabiDev is mounted hidden, so Finder never lists it). Unplugging without ejecting is what left the image needing recovery on 2026-10-21. Without the SSD, `npm install`/`npx` everywhere fail (npm cache) and the repo is unavailable. Small-file writes to the image are slow over USB (47k-file npm cache copy: ~7 min).
- Ollama model blobs (large files) live on the SSD too: `npm run ai:ollama` serves with `OLLAMA_MODELS=$DATA_DIR/ollama`. Use the Ollama **CLI** (`brew install ollama`), never the menu-bar app — it autostarts its own server with models on the Mac disk.
- Hybrid architecture: `frontend/` (Vite+React+Tailwind v4), `backend/` (Express 5, `createApp(deps)` composition root), `shared/` (`contract.ts` = the only wire contract), `ai/`, `database/schema/schema.sql` (idempotent, applied on api boot), `infrastructure/docker/`.
- One root `package.json`, no workspaces. Aliases `@`, `@ai`, `@shared` exist for frontend only; backend imports stay relative.

- **SabiDev auto-mount (2026-10-21):** macOS privacy blocks background jobs from reading `/Volumes/PortableSSD` (that, not FSKit, caused the earlier "superblock invalid" / "cannot open backing store" errors). The launchd agent `com.febriel.sabidev-mount` runs `~/Applications/SabiDev Mount.app` (Full Disk Access granted) → `~/.local/bin/sabidev-mount` → mounts the image at `~/SabiDev` within ~10 s of the SSD appearing; log `~/Library/Logs/sabidev-mount.log`. If the SSD drops off USB while the image is attached, mounts fail with "Input/output error" against the dead attachment; the script now detaches it on a failed mount so the next run (≤ 60 s) re-attaches fresh (seen 2026-10-22). Before unplugging run `Eject Sabi SSD.app` → `~/.local/bin/sabidev-eject` (takes the mount script's lock so the agent can't re-mount mid-eject; reports via notification + the same log).

## Run / verify
Processes (terminal tabs, or `.claude/launch.json` entries `api-lite`, `dev`, `whisperx`, `ollama`):
1. `npm run ai:whisperx` — whisperX sidecar on :8010 (first run: `uv` installs torch/whisperx into `ai/transcription/.venv` on the Mac (~3 GB), then downloads the `small` Whisper model + a wav2vec2 aligner into `DATA_DIR/hf` on the SSD).
2. `npm run dev:lite` — API with in-memory repos and jobs, files under `DATA_DIR`, ledger `$DATA_DIR/ledger.jsonl` (debug here first). `npm run dev:server` needs `DATABASE_URL=postgres://captions:captions@localhost:5433/captions` (`make db` starts Postgres, MinIO and Redis; Docker Desktop must be running; `.env` = copy of `.env.example`). Nothing loads `.env` for npm scripts: export `S3_ENDPOINT`/`S3_*` to use MinIO and `REDIS_URL=redis://localhost:6379` for durable jobs (`api-env.sh`-style subshell). **`make db`'s database is bound to `s3:captions`** (first booted on MinIO, as `make up` uses it): plain files there refuse to boot — export the S3 vars or use another database.
3. `npm run dev` — Vite on :5173 proxying `/api` → :3001.
4. `npm run ai:ollama` — Ollama on :11434 for "Plan edit" (shots, emphasis, emoji, translation). Not installed yet (2026-10-18): `brew install ollama` → `npm run ai:ollama` in its own tab → `ollama pull qwen2.5:3b` (~1.9 GB, served by that instance so it lands on the SSD). `OLLAMA_MODEL=qwen2.5:7b` (4.7 GB, fits 16 GB RAM) translates ja/ko/zh/hi/tl noticeably better, ~2× slower. Captions (`/run`) never need Ollama.
5. **Claude as the editor** (plan 3, spec row 10): API running (any of the above; `api-lite-fake` is enough) + optionally `npm run dev` for the live web preview → open a Claude Code session **in the repo folder** → approve the project MCP server `sabi` (`.mcp.json`: `npx tsx backend/mcp/index.ts`, `SABI_API_URL=http://127.0.0.1:3001`) → 11 tools (`list_projects inspect_project render_frame apply_actions run_job wait_job create_project upload_asset export_outputs model_catalog generate_assets`); skill `.claude/skills/sabi-editor` teaches the loop (plus `motion-graphics.md` for agent-written MGs). B-roll/brand/MG loop: `run_job plan` → `run_job broll` → `inspect_project {section: "broll"}` → `apply_actions` (`setOverlay`, `replaceOverlay` after `upload_asset`, `setBrand`, `addMotionGraphic`…) → `render_frame` → `run_job render`. One asset on demand (plan 5): `model_catalog` → `generate_assets` (fal prompt, or up to 3 Pexels candidates; no render) → `apply_actions addOverlay | replaceOverlay`; `inspect_project {section: "assets"}` lists earlier ones. The MCP client sends `x-sabi-actor: agent` (ledger attribution). `npm run mcp` runs the server by hand (stdio; logs on stderr only). A session started in another folder never sees `.mcp.json`; `claude mcp list` in the repo shows it as "Pending approval" until approved.
- `FAKE_AI=1 npm run dev:lite` (launch entry `api-lite-fake`) swaps whisperX, Ollama, **Pexels and fal.ai** for fakes (sample transcript, deterministic plan, "Spanish: …" translations, a 1×1 PNG as every stock/generated image; fake videos fail the probe and are skipped) so the whole UI can be driven with only ffmpeg + Chrome.
- B-roll providers (both optional; a project whose media source needs a missing one fails its B-roll job with `stock_unavailable` / `generator_unavailable` and keeps everything): `PEXELS_KEY` (free, https://www.pexels.com/api/, 200 req/h) for "Stock only" and as the per-beat fallback; `FAL_KEY` for "Generate (fal.ai)": `fal-ai/flux/schnell` ≈ $0.003/image (ledgered as 1 ¢), one video beat per project with `fal-ai/kling-video/v1.6/standard/image-to-video` ≈ $0.25. `creditsUsedCents` on the project sums it (no billing). Every fal call goes through `chargeGeneration` (`backend/modules/usage/spend.ts`): monthly cap `SPEND_CAP_CENTS` first (unset/empty = 2000, `0` = off, UTC months), then one `credit_ledger` row (no prompt) as soon as fal answers. `/usage` and `GET /api/usage` show it; `GET /api/catalog` lists models, availability and spend.
- Uploads accept images too (`image/png`, `image/jpeg`, `image/webp`; ≤ 50 MiB, ≤ 8192 px) for logos, overlay replacements and MG image props. Uploads from a script: `POST /api/assets/uploads/start` → `PUT /api/assets/uploads/:id` → `POST …/done` → `POST /api/projects/:id/source`.
- `npm run db:migrate` applies `database/schema/schema.sql` (idempotent) to `DATABASE_URL` (default `localhost:5433/captions`) — run it after any schema change. `npm run test:infra` = the gated tests against `make db` (Postgres, MinIO storage contract and boot checks, BullMQ runner contract incl. a dead-worker restart, a job that dies twice and a Redis outage); CI does not run them.
- `npm run verify` = typecheck (web + server) + vitest (~475 tests) + `npm run test:py` (pytest for the sidecar's `ai/transcription/timing.py` through `uv run --no-project --with pytest`: needs only `uv` — `brew install uv` on a fresh Mac — no venv or torch). Tests are colocated; the API is tested with supertest against `createApp(makeTestDeps())` (fake media/transcriber/renderer); components with `renderToStaticMarkup` (no jsdom) — handlers are reached by recording element props through a `react/jsx-dev-runtime` mock.
- **Editor (plan 4):** `/p/:id?tab=timeline|captions|broll|style|export` (lazy chunk). Every web edit is a typed action on `POST …/actions` with `render: false`; the MP4 is rendered only from **Export** (1080p, or 4K = Remotion `scale: 2`, `outputs.resolution`), and any visual edit marks `outputs.stale` until then (MCP `export_outputs` refuses stale outputs; `run_job {kind: "render", scale?: 2}`). The browser `Player` is the preview; drags preview locally (`shared/editing/applyLocal.ts`), commit once on release; undo/redo are inverse actions; an agent edit pulses the changed blocks and clears undo.
- **Fonts:** the six `BRAND_FONTS` ship as `@fontsource` packages imported by the composition (`shared/remotion/fonts.ts`), so Player and render use the same files offline. The Vite dev server needs `server.fs.allow` for the real `node_modules` path (symlink), or the font files 403.
- **Demo:** `database/seed/demo/` (1.7 MB: clip, two Pexels stills, MP4 at crf 26, SRT, VTT, `manifest.json`) is seeded on boot when there are no projects (dev:lite: every boot). Rebuild: finish a project, then `npm run demo:pack -- <projectId> [--api http://127.0.0.1:3001]`, then set the overlays' `source: "stock"` + `attribution` in the manifest. Every pack mints new asset ids (`demo-src-<stamp>`…): asset files are cached as immutable by id, so new bytes under an old id would never reach a browser that saw the old demo.
- **Privacy:** uploads and imported B-roll lose EXIF/GPS/location before they are stored (`Media.sanitize`: sharp re-encodes images upright, ffmpeg stream-copies audio/video without metadata, MP4/MOV with `-movflags +faststart` so the index comes first; unreadable → `422 bad_media`). `backend/shared/media.test.ts` also passes in the api image's Debian ffmpeg 5.1.9 (2026-10-22; every upload type: mp4, mov, mp3, wav, jpeg, png, webp): run it there by mounting `backend`, `shared`, `vitest.config.ts` and `frontend/src/test` into `captions-clone-api` and linking a side-installed vitest into `/app/node_modules` (`NODE_ENV=production` makes `npm i` skip it). ffmpeg < 6.1 has no `-display_rotation`; the test falls back to the legacy `rotate` tag. `RETENTION_DAYS` (default 30, `0` = off) — projects not opened for that long are deleted with their files, on boot and hourly (`retention: removed <n>` on stderr). Analytics: `VITE_POSTHOG_KEY` + `VITE_POSTHOG_HOST` at **build** time (compose build args), and only after the viewer clicks Allow in the first-visit banner (`localStorage` `sabi.consent` / `sabi.aid`); without keys the banner just says analytics is off.
- `npm run transcribe:sample` — real whisperX on `ai/evaluation/fixtures/tagalog-sample.wav` (Febriel reading `tagalog-sample.txt`, 16 kHz mono; **not recorded yet**, so it skips): needs `npm run ai:whisperx` running; the first `tl` run downloads the 1.26 GB aligner into `HF_HOME`. Checks aligned `tl` timings and the all-estimated fallback for `ms` (no aligner).
- `npm run render:sample` — real Remotion renders (needs Google Chrome; ~2 min; also 4K and a bundled display font): captions, cuts, a still, a top-band overlay, a brand-graded clip with an MG, a throwing MG (⚠ placeholder), an MG whose image fails to load (⚠ image) and an endless-loop MG (render fails in ~40 s); plus the MG sandbox (plan 6): frame-exact MG frames, a canary server no MG request reaches (fetch, XHR, WebSocket, beacon, img, CSS url, nested frame, navigation), image props drawn from bytes, a silent MG → ⚠ in 5 s (in the MP4 and on its still), two MGs in a 4K export, still = MP4 frame, brand fonts inside the sandbox, and `renderStill`'s MG problems; the layer tests sample pixels with ffmpeg.
- **MG sandbox page (plan 6):** `frontend/public/mg-sandbox.html` is generated and committed: `npm run build:mg-sandbox` after changing `shared/remotion/sandbox/`, `shared/remotion/mgRuntime.ts` or the React/Remotion versions (`backend/modules/mg/sandbox.test.ts` fails when it is stale), then restart the API (it bundles `frontend/public` into Remotion once per process). Vite (dev and preview) and nginx serve it with `Content-Security-Policy: sandbox allow-scripts; frame-ancestors 'self'`; the frames themselves carry `sandbox="allow-scripts"` (so a navigation can't land unsandboxed at Sabi's origin), and the page refuses to run at a real origin. **The Claude desktop browser pane cancels loads of iframes that carry a `sandbox` attribute** (`net::ERR_BLOCKED_BY_CLIENT`), so MGs show ⚠ there after 15 s: check MGs in Chrome/Safari or with `render_frame`.
- **Editor CSP (plan 6, spec row 27):** `frontend/src/csp.ts`, injected first in `<head>` by the `sabi-csp` plugin in `vite.config.ts` (dev hashes the React refresh preamble; the build has no inline script). A new third-party origin (another analytics host, a CDN) needs a line there; `VITE_POSTHOG_HOST` is added to `connect-src` automatically.
- **Renders use Remotion's own `chrome-headless-shell`** (v157, 570 MB, downloaded once on the first render into `~/Developer/.sabi-deps/.remotion`; `npm run deps` links every checkout's `node_modules/.remotion` there so worktrees share one copy; `REMOTION_BROWSER_EXECUTABLE` overrides). The installed Google Chrome was 4× slower: it waited on its frame clock for every screenshot (~10 fps whatever the concurrency, frame size or content). The renderer keeps **one browser per process** for every render and `GET /frame` still, and both servers **warm it at boot** (bundle into `$TMPDIR/sabi-remotion-bundle-<checkout hash>` + browser, ~1.2 s, logged as `renderer warm in …`). Measured 2026-10-22 on the 17 s demo (M4): export render 62 s → 14 s; a `/frame` still 0.5 s. Not worth it there: more than 5 tabs (content-bound at ~40 fps; remaining cost is video decode ~30 % and the brand grade ~15 %) and hardware encoding (VideoToolbox, +4 %, bitrate instead of crf).
- **Audio fades at cuts (export only, 2026-10-22):** with enabled cuts the renderer has Remotion write picture and audio apart (`separateAudioTo` WAV), then one ffmpeg pass muxes them (`-c:v copy`, AAC 320k) with an `aeval` gain that falls to 0 over the last 15 ms before each join and rises over 15 ms after (`CUT_FADE_MS`, `cutFadeFilter` in `backend/shared/renderer.ts`), so a phase jump at a join never clicks. The distance to the nearest cut is a binary search of nested `if()` (lazy in ffmpeg); a `min()` over every cut added ~5 s per minute of audio at 80 cuts, the search costs nothing measurable at 300. Remotion's own `volume` steps once per video frame (33 ms), too coarse. The editor's Player has no fades. Tested on a 440 Hz tone cut off-cycle (step at the join 0.47 → under 0.07).
- **No Sabi files in iCloud (2026-10-22):** Desktop syncs to iCloud on this Mac and had evicted `~/Desktop/Reverse Engineer/` (the captions.ai notes and `test-clip-9x16.mp4`) to placeholders. The folder now lives in `~/Developer/Reverse Engineer/`; the old copy is in the Trash. `export_outputs` refuses any folder iCloud syncs and points at `~/Movies/Sabi`. A folder counts as synced when it, or a parent below `$HOME`, has a `com.apple.file-provider-domain-id` xattr starting with `com.apple.CloudDocs`. macOS puts that xattr on `~/Desktop`, `~/Documents` and `~/Library/Mobile Documents` (`syncedToICloud` in `backend/mcp/tools.ts`). Tests can't write that xattr, so the parent-folder walk is tested with an injected reader, and the real refusal is tested against `~/Library/Mobile Documents`, which is read-only.
- **Render temp lives on the Mac (2026-10-21):** `dev:lite`, `dev:server` and `render:sample` set `TMPDIR=~/Developer/.sabi-tmp` (beside `.sabi-deps`), where Remotion puts Chrome's profile and its downloads (cleaned after each render; the Mac disk had 12 GiB free then). With the profile on the SabiDev image (mounted `nobrowse,noowners`) headless Chrome started in 3.6 s and hung ~18 s on teardown ("Teardown watchdog expired"), so every render failed "Timed out after 30000ms while setting up the headless browser". A process started outside those scripts inherits the system TMPDIR (also on the Mac).
- **Docker stack (plan 5):** `make db` = Postgres (127.0.0.1:**5433** — a Homebrew `postgresql@18` service owns 5432; data in `~/SabiDev/docker/postgres`), MinIO (`cgr.dev/chainguard/minio`, `minio/minio` left Docker Hub; 127.0.0.1:9000/9001; data `$DATA_DIR/minio`), Redis (127.0.0.1:6379, no password, `~/SabiDev/docker/redis`; AOF only — `--save ""`, no `dump.rdb`, so deleted prompts can't outlive the AOF rewrite). Postgres and Redis can't live on the ExFAT SSD: their entrypoints `chown` the data dir and fail on macOS `._*` AppleDouble files after a recreate. `make up` builds the Debian api image (ffmpeg, Chrome headless shell, `fonts-noto-color-emoji`; 2.2 GB) + nginx web on :8080 and renders the demo end to end on MinIO + Redis; `docker builder prune -f` afterwards (Mac disk). Postgres (`pg_isready`), MinIO (`mc ready local`) and Redis (`redis-cli ping`) have healthchecks and the api waits for all three (`depends_on: service_healthy`): its boot checks exit on a service that isn't answering yet. The api's scratch is bind-mounted from the SSD (`${DATA_DIR}/docker-work` → `/work`, `WORK_DIR`), not the Docker VM's disk on the Mac. Checked 2026-10-23: a cold `make down && make up` brings the three up healthy before the api, which boots on MinIO + Redis; a demo render through nginx puts its flat scratch file in `docker-work/sabi-work/renders/` and leaves it empty. `npm run build:server` → `dist-server/index.mjs` (ESM, packages external). CI (`.github/workflows/verify.yml`): `npm ci` → `npm run verify` → `npm run build` on Ubuntu with uv + ffmpeg.
- **S3 scratch:** with `S3_ENDPOINT`, ffmpeg and Remotion work on local copies in `<WORK_DIR>/sabi-work` (`WORK_DIR` defaults to `$TMPDIR`, the Mac disk; Sabi names the folder itself so a sweep never reaches anything else in `WORK_DIR`); with files, scratch is `$DATA_DIR/work` (same disk, so `put` is a rename). Scratch names are flat (`renders/<project>-<id>.mp4`, `frames/<project>-<id>.png`): no folder per project (1 MiB each on ExFAT). At boot `createStorage` (and dev:lite) sweeps scratch: files nothing touched for an hour go, with folders that were stale and end up empty; fresh files stay, because several API processes can share one scratch folder (worktrees, a second dev server that then finds its port taken).
- Local ffmpeg has no libass/freetype: all text is drawn by Remotion; ffmpeg only probes and extracts 16 kHz WAV, with `-protocol_whitelist file` + a format whitelist (uploads are untrusted).

## Decisions
- **Claude is the editing agent, on subscription only (spec §11 row 10, 2026-10-20):** a Claude Code sidebar session drives projects through Sabi's MCP server (`backend/mcp`, `.mcp.json`, skill `.claude/skills/sabi-editor`). The backend never calls Claude or any Anthropic API; web buttons stay on Ollama. Plan 3 (B-roll) is paused on `worktree-broll-and-overlays` until the MCP plan lands.
- **MCP server shape (plan 3):** `backend/mcp` is an HTTP client of the API, never an in-process import (works with dev:lite and dev:server; the web preview updates over SSE). Writes go through `POST /api/projects/:id/actions` — typed actions, all-or-nothing, guarded by `baseVersion` = the `updatedAt` Claude last saw (`409 stale` → re-inspect; ms resolution). `render_frame` uses `GET …/frame` = Remotion `renderStill` with `captionVideoProps`, so frames are **output** time and match the export; `inspect_project` prints source times plus `→ out` times when cuts are on. Tool results stay small (summary lists capped at 30, phrases paged, search instead of dumps). File tools only touch paths under `$HOME`; `export_outputs` never overwrites or follows an existing file (`<title> (n)`).
- **Motion graphics = Remotion components, not HyperFrames (spec row 11):** the agent sends plain JS+JSX; the server transpiles it with the TypeScript compiler (`typescript` is a runtime dependency) and vets the AST (`backend/modules/mg/compile.ts`: no imports/exports, a denylist of globals, network, timers, code-from-string, HTML-from-string, spread attributes and string-built property names) and stores `code` + `compiled`. The server **never executes** it, and since plan 6 no Sabi page does either (spec rows 24–27): `compiled` runs only inside its MG's own sandbox page (`/mg-sandbox.html`: opaque origin, CSP `default-src 'none'`, fonts and image props handed in as Blobs, page ⇄ sandbox over a `MessageChannel`), the same in the Player, `GET /frame` and the MP4; renders wait for each MG frame, the Player doesn't. The denylist stays as the agent's early warning (`400 bad_code`), not the boundary. ⚠ when the code throws, an image fails, the MG navigates or stops answering for 5 s (15 s to start); `render_frame` lists why (`x-sabi-mg-problems`). The web edits MG props (B-roll panel **Edit**), never code.
- **Brand kit (row 12):** `project.brand` (palette, `fontFamily`, `logoAssetId`, `grade`) recolours captions (text, accent = active word + keywords, primary = nouns/pictorial), feeds every MG as `item.brand` (its `fontFamily` is the loaded CSS family, e.g. `Montserrat Variable`), and grades footage + B-roll (CSS saturate/contrast + a soft-light tint of `primary`). Layer order in `CaptionVideo`: footage → B-roll overlays → tint → MGs → captions. Caption look = preset → brand kit → `project.captionStyle` (`effectiveTemplate`, spec row 16).
- **One write path + explicit export (plan 4, spec row 14):** the web app writes only through `POST …/actions` (`render: false`), the job routes, uploads, `POST /source` and `DELETE /api/projects/:id` (both `409 busy` while the project has a queued or running job); `PUT /phrases`, `PUT /template`, `PATCH /plan`, `PATCH /projects/:id` are gone. `applyActions` on the server and the browser's optimistic/drag preview share one fold (`shared/editing/applyLocal.ts`; only `replaceOverlay`, `setBrand`, `addMotionGraphic` and MG code/props stay server-side); the fold is sequential (each action sees the earlier ones). Conflicts: a stale commit rolls back, refetches and offers **Retry on the new version**; the agent's edit is never overwritten.
- **Timeline in source time (plan 4):** stored times stay source time; the timeline draws source time with enabled cuts shaded, the Player runs output time (`mapTime` / `toSourceTime`). Gestures and keyboard are pure reducers (`features/editor/timeline/{layout,gestures,keyboard}.ts`); tracks are `touch-action: pan-y`, so horizontal swipes on empty space pan the timeline in JS. On phones the timeline sits under the sticky preview and transient notices float above the tab bar.
- **Fonts bundled, not Google Fonts (spec row 15):** `BRAND_FONTS = Inter, Montserrat, Poppins, Bebas Neue, Playfair Display, Space Grotesk`; the composition holds the first frame (`delayRender`, once per page) until every face is loaded.
- **Money (plan 5, spec rows 19–20):** one path to fal (`chargeGeneration`: cap → generate, and the ledger row is written the moment fal accepts the paid request, so a timeout or failed import still counts; videos get a 10-min deadline, images 3; a miss is `generator_timeout`, distinct from `generator_unavailable` = no key / refused, nothing billed); B-roll beats over the cap fall back to Pexels with warning `over_cap`; `POST …/generate` answers `402 over_cap` before queueing. Ledger rows keep no prompt or media and outlive deleted projects; `creditsUsedCents` stays the per-project display total. `FAKE_AI=1` ledgers in memory (the fake generator spends nothing).
- **Jobs are data (plan 5, spec row 22):** `enqueue(projectId, kind, {input, actor, prevStatus})`, handlers registered in `createApp` (`backend/app/jobs.ts`) load the project when they start; one job at a time across the machine (`QUEUED` = waiting behind another project). `REDIS_URL` → `BullJobRunner` (in-process worker, finished jobs kept 7 days/200 and deleted with their project — they hold prompts; the delete ends with an AOF rewrite, retried every 200 ms for up to a minute while one already running holds the old snapshot; Redis writes no RDB snapshots, so that rewrite is the only copy to clean); a job interrupted by a restart comes back via BullMQ's stalled check (~30–60 s): captions/plan re-run, broll/generate go through `noRerun` (previous status back, MP4 stale, FAILED `interrupted`, fal never called twice; a project no longer running means the first attempt finished and only its result was lost — BullMQ lost the lock — so it fails `already_ran` and touches nothing). A job that stalls twice is failed by BullMQ without its handler; `onAbandoned` gives it the same put-back. The Queue's connection fails reads in ~2 s while Redis is down (routes answer 500); only the Worker's blocking connection waits (`maxRetriesPerRequest: null`). BullMQ 6 also has a Postgres backend — the option if Redis ever becomes a burden.
