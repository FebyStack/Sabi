# Editor UI (plan 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A touch-first editor (phone and desktop web) where every edit — timeline drags, caption words, B-roll, style, brand — is one typed action batch on the same `POST …/actions` path the Claude agent uses, the browser `Player` is the live preview, export is explicit (1080p / 4K), agent edits appear live, conflicts are visible and retryable; plus the first-run demo project, the consent banner with the 30-day retention it promises, and one staged progress model.

**Architecture:** The project document stays the single source of truth in TanStack Query; a small editor store (selection, playhead, zoom, drag, undo, conflict) lives beside it. Pure modules decide everything — `shared/editing/applyLocal.ts` folds the "local" actions for both the server (`applyActions` delegates to it) and the browser (optimistic preview during a drag, undo via inverse actions); `timeline/layout.ts` + `gestures.ts` turn pointer events into actions without touching the DOM — so the node-only test setup (`renderToStaticMarkup`, no jsdom) still covers the behaviour. Layout is one route `/p/:id` with a `?tab=` panel: on phones a bottom tab bar under a sticky preview, on ≥ 1024 px a preview + panel rail with the timeline always visible. Design tokens are Tailwind v4 `@theme` variables; primitives are five small components on native elements (`<dialog>` for sheets — no Radix). Fonts are bundled OFL files imported by the composition, so the Player and the render browser load the same bytes.

**Tech Stack:** existing (React 19, Vite 7, Tailwind 4, TanStack Query 5, react-router 8, Remotion 4.0.536 `Player` + `delayRender`, Express 5, zod 4, MCP SDK) + `@fontsource-variable/{inter,montserrat,playfair-display,space-grotesk}`, `@fontsource/{poppins,bebas-neue}` (OFL, `^5.2.0`). No Zustand, no Radix, no PostHog SDK (HTTP capture), no jsdom.

## Global Constraints

- **No Anthropic API, no model calls from the web app.** The only automation buttons (Plan edit, translate, Add B-roll) start the existing Ollama/Pexels/fal jobs. Claude edits through the MCP server; this UI must show those edits live.
- **One write path.** The web app writes projects only through `POST /api/projects/:id/actions` (`baseVersion` = the `updatedAt` it last saw, `render: false`), the job routes (`POST /run`, `/plan`, `/broll`, `/render`), `POST /source`, uploads, and the new `DELETE /api/projects/:id`. `PUT /phrases`, `PUT /template`, `PATCH /plan`, `PATCH /projects/:id` and their inputs/tests are **deleted** (spec row 14). MCP keeps working unchanged except where Task 14 says.
- **Explicit export.** A web action never renders. When `applyActions` reports `rerender` and the call has `render: false`, the route stores `outputs: { ...outputs, stale: true }`; `renderOutputs` always returns fresh outputs (no `stale`). `POST /render` takes `RenderInput { scale: 1 | 2 }` (`2` = 4K, `outputs.resolution: "4k"`); every other job renders at the project's current resolution (`outputs.resolution === "4k" ? 2 : 1`).
- **Time bases.** Everything stored is source time (as plans 2–3b). The timeline draws source time with enabled cuts shaded; the Player runs output time. Conversions: `mapTime` (source → output, exists) and the new `toSourceTime(outMs, cuts)` (output → source; a time at a cut boundary maps to the cut's end).
- **New actions** (exact schemas in Task 1): `setShotBounds`, `retimePhraseRange`, `setWordEmphasis`, `setPhraseEmoji`, `setCaptionStyle`. Limits: `MIN_SHOT_MS = 500`, `MIN_PHRASE_MS = 200`, emoji ≤ 16 chars, caption `sizePx` 40–120, `y` 0.5–0.9, `weight` ∈ {400, 700, 900}. Shots stay contiguous: moving a boundary moves the neighbour's matching edge; the first start and the last end never move (`out_of_range`). Phrase ranges never overlap neighbours (`overlap`).
- **Fonts** (spec row 15): `BRAND_FONTS = ["Inter", "Montserrat", "Poppins", "Bebas Neue", "Playfair Display", "Space Grotesk"]`; `brand.fontFamily` and `captionStyle.fontFamily` are this enum; CSS families come from `fontCssFamily()` (fontsource registers variable fonts as `"<Name> Variable"`); the composition waits for `document.fonts.ready` under `delayRender` so a render never falls back to a system font.
- **Touch and keyboard** (spec row 1, blueprint §10.10): every control ≥ 44 px; drag handles have a 44 px hit area; tracks use `touch-action: pan-y` (vertical scroll stays native, horizontal drags and two-finger pinch are ours); blocks are `<button>`s with an `aria-label` of `"<track> <label> <m:ss>–<m:ss>"`; `←/→` nudge the selection 100 ms (`Shift` 1 000 ms), `Delete` removes an overlay/MG, `Escape` deselects, `Space` toggles play; notices are `aria-live="polite"`; `prefers-reduced-motion` disables the change-highlight pulse and sheet slide.
- **Design tokens** (blueprint §10.5): CSS variables in `frontend/src/styles/index.css` under `@theme` — surfaces `surface-0 #0a0a0a`, `surface-1 #141414`, `surface-2 #1f1f1f`, `line #2a2a2a`; text `ink #f5f5f5`, `ink-muted #a3a3a3`; one accent `accent #FFD60A` with `accent-ink #0a0a0a`; `danger #ff453a`, `warn #ffb020`, `ok #30d158`; track tones `shot-hook #f59e0b`, `shot-th #737373`, `shot-broll #0ea5e9`, `shot-thb #8b5cf6`, `cut #ef4444`, `caption #e5e5e5`, `overlay #0ea5e9`, `mg #a78bfa`; radii `4 / 8 / 12 / 20` px; type scale `xs 12/16`, `sm 14/20`, `base 16/24`, `lg 20/28`; motion `150 ms` (state) / `250 ms` (layout), ease `cubic-bezier(.2,.8,.2,1)`. Components use token classes (`bg-surface-1`, `text-ink-muted`, `bg-shot-broll`), never raw hex.
- **Privacy** (spec rows 2, 18): nothing leaves the machine unless the viewer accepted analytics **and** `VITE_POSTHOG_KEY` + `VITE_POSTHOG_HOST` are set at build time; the consent choice and the anonymous id live in `localStorage` keys `sabi.consent` / `sabi.aid`; every `localStorage` access is wrapped (private mode, blocked storage). The retention sweep deletes projects whose `last_access` is older than `RETENTION_DAYS` (default `30`, `0` disables), files included, on boot and hourly.
- **Demo** (spec row 17): `database/seed/demo/` ≤ 25 MB (`clip.mp4` as uploaded, stills ≤ 1 MB each, outputs re-encoded `-crf 26`); seeded only when `projects.list()` is empty; `project.demo: true`; ids fixed (`demo`, `demo-src`, `demo-ov-0`, `demo-ov-1`, `demo-mp4`, `demo-srt`, `demo-vtt`).
- **Responsive**: `< 1024 px` one column, preview sticky at the top (max `45vh`), bottom tab bar (5 tabs, 56 px + safe-area inset), panel scrolls; `≥ 1024 px` grid `minmax(320px, 38%) 1fr` (preview + transport | tab strip + panel), timeline full width below, no tab for it. Phone gutter 16 px; no horizontal page scroll (the timeline scrolls inside its own container).
- **Performance** (blueprint §10.9): the editor route is `React.lazy`; drag previews patch the Player's props locally (`applyLocal`), never the server; range/colour inputs commit debounced `300 ms`; the project query is updated from the action result (`setQueryData`), with a refetch only on SSE/conflict.
- **SEO** (blueprint §10.8): the app is local and `noindex` (already in `index.html`); this plan adds only a web manifest + theme colour so a phone can pin it. Marketing pages are out of scope (spec row 6: standalone app, no site).
- Mobile-first, TDD, colocated tests, `npm run verify` **and** `npm run build` green after every task; backend imports relative; `database/schema/schema.sql` changes are `ADD COLUMN IF NOT EXISTS`; commits carry no AI co-author or "Generated with" lines (`.githooks/commit-msg` strips them). One whole-branch review at the end (owner's rule), not per task.

## Review Focus

1. **The agent edits while the user is mid-drag**: the drag's commit lands on a stale `baseVersion` → the optimistic patch is rolled back, the project refetched, a notice offers **Retry on the new version**, and the agent's edit is never overwritten. → Task 5 tests `a stale commit rolls back the optimistic patch and offers retry`, `retry re-sends the same actions on the new baseVersion`.
2. **An agent edit arrives while the tab is open**: the Player shows it without reload, the changed blocks pulse, the undo stack is cleared (undoing would fight the agent). → Task 5 test `an external version clears undo and names the changed layers`; the existing backend test `actions publish a project event` stays green.
3. **A 0.4 s shot or overlay on a phone** is too narrow to grab: blocks keep a minimum width and the selection bar nudges the selected block precisely. → Task 7 tests `blocks keep a minimum width`, `the selection bar nudges an overlay inside its shot`.
4. **Dragging past a constraint** (overlay past its shot, phrase into its neighbour, shot under 500 ms): clamped while dragging; the server rejects the same inputs from any client. → Task 6 test `dragBounds clamps every handle`; Task 1 tests `retimePhraseRange refuses overlap`, `setShotBounds keeps neighbours at least 500 ms`.
5. **Edits after the last render**: the export panel says the MP4 is stale and offers a render; a 4K render doubles the output dimensions; the agent's summary shows `stale`. → Task 2 tests `an action without render marks outputs stale`, `render at scale 2 doubles the output size`; Task 11 test `shows the stale notice`; Task 14 test `summary flags stale outputs`.
6. **Consent declined, or storage unavailable (private mode)**: nothing is sent, the app never throws. → Task 12 tests `track is a no-op without consent or keys`, `consent survives a throwing localStorage`.
7. **Retention**: a project untouched for 31 days disappears with its files; one opened yesterday stays; a project with a running job is never deleted. → Task 12 test `sweep removes only stale projects and their files`; Task 2 test `delete refuses a busy project`.
8. **Dark brand text on a dark background**: the Style panel warns before the user exports unreadable captions. → Task 10 test `warns when caption contrast is under 3:1`.

## Blueprint coverage and trade-offs (AI Website Architect sections)

- **Folder / component architecture:** `features/editor/{layout,store,actions,timeline,panels}` (Tasks 4–11), `components/ui` primitives (Task 4), `features/consent` (Task 12), `features/projects` for list/upload; pure modules sit beside their components and carry the tests. Trade-off: feature folders over the blueprint's `src/app` + `src/lib` split because the app has one editor route and one API client; splitting further would be structure without a second consumer.
- **Design system:** tokens as Tailwind v4 `@theme` variables (Task 4) — one accent, four radii, four type steps, two durations; five primitives on native elements. Trade-off: no Radix — `<dialog>` gives focus trapping and `Escape` for free and the app has one dialog shape (the sheet); Radix would add ~40 KB for popovers the spec does not ask for. Revisit if menus/popovers arrive.
- **Responsive layouts:** one route, `?tab=` panels, bottom tab bar on phones, rail + always-visible timeline on desktop (Task 4); the timeline itself scrolls and zooms inside its container, never the page. Trade-off: tabs over a long scroll page because the preview must stay visible while editing on a phone (spec row 1).
- **State management:** server state in TanStack Query (project, events), editor state in a tiny external store (Task 5), undo as inverse actions. Trade-off: no Zustand (one store, `useSyncExternalStore` suffices), no CRDT (solo user; the agent and the browser already serialise through `baseVersion`).
- **SEO:** `noindex` app, manifest only (Task 4). The spec locks a standalone local app with no marketing site (row 6), so SSG/landing pages are out of scope by decision, not oversight.
- **Performance:** lazy editor chunk, local drag preview, debounced commits, cache updates from action results (Tasks 4, 5, 7, 10); fonts bundled once for Player and render (Task 3). Trade-off: the Player re-renders props on every drag frame — acceptable for ≤ 10-minute clips; virtualising the caption list is deferred until a transcript exceeds ~1 000 phrases.
- **Accessibility:** 44 px targets, roles on tracks/blocks/switches/radios, keyboard nudges and deletes, live-region notices, reduced motion, contrast warning (Tasks 4, 6, 7, 10). Not done: full screen-reader description of drag (nudging covers it).
- **Analytics:** consent-gated funnel events to PostHog over HTTP, off by default (Task 12). Trade-off: no SDK — no session replay, no autocapture, no cookies, which is exactly spec row 2.
- **Deployment:** unchanged compose; fonts ride in the Vite and Remotion bundles; the demo bundle ships in the api image with `database/`; `RETENTION_DAYS` and `VITE_POSTHOG_*` are env (Tasks 12–13). CI stays `npm run verify` + the gated render tests.
